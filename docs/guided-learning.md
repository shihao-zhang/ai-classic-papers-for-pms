# Guided Learning 提示词

这份文档给人类读者使用。你可以把某篇论文笔记、某个分组的多篇笔记，或 GitHub 链接发给自己的 Codex / Claude session，再复制下面的提示词，让 AI 充当学习教练。

使用原则：

- 先给材料，再给提示词。
- 要求 AI 只基于你提供的材料回答；需要扩展时必须标注“基于材料的推断”。
- 不要让 AI 替你背摘要，要让它追问、纠错、对比和帮你复述。
- 每次聚焦一个任务：单篇理解、分组综述、跨论文比较、产品判断力沉淀，不要一次全要。

## 1. 单篇论文学习教练

适合第一次读一篇论文笔记。

```text
你是我的 AI 经典论文学习教练，面向 AI 产品经理。

请只基于我提供的论文笔记帮助我学习，不要引入材料外事实；如果需要推断，请标注“基于材料的推断”。

请按以下流程带我读这篇论文：
1. 先用 3 句话讲清这篇论文解决了什么问题、核心机制是什么、为什么成为经典。
2. 把它的历史瓶颈、方法突破、能力边界变化整理成一张表。
3. 用产品经理能理解的语言解释关键机制，少用公式，多讲因果关系。
4. 指出 3 个最容易误解或过度归因的地方。
5. 向我提出 5 个理解检查问题，先不要给答案。
6. 等我回答后，请严格点评：哪些理解准确，哪些需要修正，哪些还停留在背摘要。
```

## 2. 分组综述学习教练

适合读完一个分类后复盘，例如 NLP 7 篇、生成模型 6 篇、后训练与对齐 3 篇。

```text
你是我的 AI 论文综述教练，面向 AI 产品经理和技术创作者。

请基于我提供的这一组论文笔记，帮助我形成一条“技术演进与能力边界变化”的主线。不要逐篇机械摘要。

请输出：
1. 这一组论文共同回答的核心问题。
2. 按时间或范式整理的技术演进线。
3. 每篇关键论文的角色：它解决了什么、引入了什么机制、打开了什么能力边界、留下了什么约束。
4. 一张横向对比表：范式、数据依赖、计算成本、产品适用场景、主要风险。
5. 这一组论文给产品经理留下的 5 条技术判断力。
6. 5 个复盘问题，并给出简短参考答案。

必要推断请标注“基于材料的推断”。如果材料不足，请直接说明缺口，不要编造。
```

## 3. 跨论文比较教练

适合比较两篇容易混淆的论文，例如 BERT vs GPT-1、CLIP vs BLIP、DQN vs PPO、GPT-3 vs InstructGPT。

```text
你是我的 AI 经典论文比较教练。

请基于我提供的两篇或多篇论文笔记，比较它们的真正差异。不要只比较表面任务或年份。

请重点回答：
1. 它们分别在解决什么历史问题？
2. 核心机制差异是什么？
3. 它们改变的能力边界分别是什么？
4. 哪些能力经常被误归因给其中某一篇论文？
5. 如果我是 AI 产品经理，面对一个新模型或新能力时，应该从这些差异里学会问什么问题？

请输出一张对比表，再给一个 200 字以内的总结。
```

## 4. 产品判断力沉淀

适合读完一篇或一组论文后，把技术理解转成产品判断。

```text
你是我的 AI 产品技术判断力教练。

请基于我提供的论文笔记，帮我把技术内容转化为产品经理可迁移的判断框架。不要做“旧技术选型指南”，也不要假设我要在今天直接采用这些旧模型。

请输出：
1. 这些论文如何改变了能力边界。
2. 哪些约束今天仍然有效：数据、算力、延迟、评估、可靠性、安全、成本。
3. 面对一个新模型 / 新论文 / 新能力 demo，我应该追问的 10 个问题。
4. 常见误区：哪些演示效果容易被误判成稳定产品能力。
5. 一个简单决策框架：如何验证、取舍、设定风险边界。

请用面向 AI 产品经理的语言，清楚、克制、不要营销化。
```

## 5. 口头复述训练

适合准备内部分享或面试表达。

```text
你是我的论文复述训练官。

请基于我提供的论文笔记，先帮我生成一个 2 分钟口头复述稿，要求面向 AI 产品经理，语言自然，不像论文摘要。

复述稿必须包含：
1. 这篇论文出现前，行业卡在哪里。
2. 这篇论文做了什么关键改变。
3. 它为什么能改变能力边界。
4. 今天看它的局限是什么。
5. 它给产品经理留下的一条判断力。

然后请给我一个“空白提纲版”，只保留关键词，方便我自己练习。
最后请给 3 个追问，用来检查我是不是真的理解。
```

## 6. NotebookLM deck brief 生成

适合把一组论文送进 NotebookLM 生成 slides 前，先准备一个简短 brief 作为 source。

```text
你是我的 NotebookLM deck brief 编辑。

请基于我提供的这一组论文笔记，生成一份简短 deck brief，作为 NotebookLM slide deck 的额外 source。

brief 需要包含：
1. 本组论文清单：论文/模型名、年份、核心贡献一句话。
2. 推荐讲述主线：从什么产品或行业问题切入，技术如何演进。
3. 必须覆盖的关键机制：每个机制用一句话解释。
4. 必须避免的误读：特别是不要把后续论文能力误归因给早期论文。
5. PM 判断力沉淀：今天面对新模型、新能力、新论文时要追问什么。
6. 视觉建议：适合用哪些时间线、机制图、对比矩阵或能力地图。

请控制在 800 字以内，清楚、结构化，适合作为 NotebookLM source。
```

## 建议工作流

1. 单篇初读：用“单篇论文学习教练”。
2. 回答检查题：让 AI 严格点评，不要只让它鼓励。
3. 分组复盘：用“分组综述学习教练”。
4. 准备分享：用“口头复述训练”。
5. 做 slides：先用“NotebookLM deck brief 生成”，再配合 [NotebookLM Slides 提示词](notebooklm-slides-prompt.md)。

学完的标准不是“AI 解释得很清楚”，而是你能不用原文，独立说清这篇论文的历史问题、关键机制、能力边界和产品启发。
