# NotebookLM Slides 提示词

用于把每个分类的论文笔记生成一份系列化综述 slide deck。使用时，把同一分类下的 GitHub Markdown 笔记作为 NotebookLM sources，再把下面提示词粘贴到 NotebookLM 的 slide deck 自定义提示词中。

## 通用提示词

```text
请基于我提供的这一组论文笔记，生成一份中文 detailed slide deck，面向 AI 产品经理和技术创作者。

请不要逐篇机械摘要，而是把这些论文组织成一条“技术如何演进、能力边界如何被改写”的主线：用一个真实的产品/行业问题开场，讲清每个阶段遇到的瓶颈、代表论文的角色、核心方法差异和能力跃迁。

结尾不要做“旧技术选型指南”，而要沉淀产品经理的技术判断力：这些论文如何改变能力边界，哪些约束至今仍有效，以及今天面对新模型、新能力、新论文时应该如何提问、验证和避坑。

页数根据论文数量和复杂度自适应，不要压缩成 executive summary。每个关键技术阶段至少展开 1 页；关键论文需要有机制/贡献解释；同一范式下的多篇论文可以合并成对比页。整体以讲清主线为准，避免凑页数和重复内容。

请自然加入这些内容形态：问题引入、技术演进时间线、关键机制图、范式对比、能力边界地图、今天仍有效的约束、常见误区、PM 追问清单、复盘检查题。必要推断请标注“基于材料的推断”，不要编造材料外信息。

设计上请保持同一系列感，但不要过度模板化。整体像“高质量公开课 + 咨询汇报”：16:9 横版，浅色或浅暖色纸感背景，深色正文，少量克制强调色；信息密度高但留白充足。优先使用时间线、矩阵、流程图、分层图和简洁技术示意。避免大面积绿色背景、强渐变、卡通插画、营销风标题和装饰过重的页面。每页标题要有观点，正文控制在 3-5 个要点，并补充适合讲解的 speaker notes。
```

## 使用建议

- 每次只放入一个分类的论文笔记，例如 CV 10 篇或 NLP 7 篇。
- 不要额外指定固定页数，让 NotebookLM 根据论文数量和范式跨度决定信息密度。
- 如果生成结果过像 executive summary，追加要求“展开关键机制页和章节复盘页”。
- 如果视觉过度偏绿或模板化，追加要求“采用浅暖色纸感背景，强调色只少量使用”。
