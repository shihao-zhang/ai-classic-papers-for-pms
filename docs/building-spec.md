# 搭建规范

本规范约束这个学习项目如何持续搭建。它是项目内容规范，不是 agent 行为约束。

## 定位

本项目不是论文链接合集，而是面向 AI 产品经理的经典论文学习系统。每篇笔记都要帮助读者形成可复述、可迁移的理解。

## 每篇笔记必须回答

1. 这篇论文解决了什么问题？
2. 这个问题为什么在当时重要？
3. 论文提出了什么核心方法？
4. 关键设计取舍是什么？
5. 它如何影响后续 AI 技术路线？
6. 对 AI 产品经理有什么启发？
7. 今天看，它有哪些局限、争议或已过时之处？

## 学习验证

每篇论文必须包含“理解检查”，提供 3-5 个问题。问题优先采用开放题，用来确认读者是否真正理解，而不是只读完摘要。

每道理解检查题下附一个默认收起的折叠式“参考要点”（`<details>` 块），放 2-4 条要点而不是范文：

- 默认收起，避免读者一眼看到答案、产生“看懂了”的错觉；点开才看，保留主动回忆。
- 给“要点”而非唯一标准答案，保持开放题的开放性，也方便自学者自评。
- 要点应能从正文直接推出，不引入正文以外的新信息。

此约定为新增标准，自 ViT 起的批量深化笔记开始采用；存量已达标笔记按计划逐步回填。

完成一篇论文的标准不是“看完”，而是学习者能够用自己的话解释：

- 问题背景
- 方法逻辑
- 影响范围
- 产品启发
- 局限边界

## 写作风格

- 中文为主，保留关键英文术语。
- 先讲人话，再补技术名词。
- 不使用大段公式推导，除非公式本身是论文贡献的核心。
- 面向产品判断，而不是面向论文复现。
- 明确权衡，不隐藏不确定性。

## 引用边界

- 不上传论文 PDF。
- 不大段复制论文原文、微信文章或社区文章。
- 可以放论文官方链接、arXiv 链接、项目链接。
- 必要短引文必须少量、注明来源，并服务于解释。

## Review 标准

每篇笔记通过前需要满足：

- 结构完整。
- 没有明显事实错误。
- 没有把后续论文贡献误归给当前论文。
- 对 AI 产品经理的启发具体，不停留在“很重要”“很有价值”。
- 理解检查能暴露真实理解，而不是背诵标题。
