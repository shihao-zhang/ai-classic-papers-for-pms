# Flamingo：Flamingo: a Visual Language Model for Few-Shot Learning

> 分类：多模态与视觉语言  
> 年份：2022  
> 论文：https://arxiv.org/abs/2204.14198  
> 状态：draft

## 一句话

Flamingo 把一个已经很强的语言模型“接上眼睛”，让它能在不为每个任务重新微调的情况下，通过少量交错的图文示例完成看图问答、图像描述、视频理解等多模态任务。

## 背景问题

在 Flamingo 之前，多模态模型已经有两条很重要的路线。

一条是 CLIP 这类图文对齐模型：它很擅长判断“这张图和哪段文字更匹配”，适合检索、分类、排序，但不天然擅长生成长答案、跟随上下文、做开放式问答。

另一条是大语言模型：GPT-3 已经证明，只要在 prompt 里给几个例子，模型就能做 few-shot learning，也就是不用更新参数，只靠上下文临时学会任务格式。但语言模型只看文字，看不到图片或视频。

当时真正卡住的问题是：能不能把视觉能力接到强语言模型上，同时保留语言模型的少样本上下文学习能力？更具体地说，一个模型能不能读这样的上下文：

```text
<图片1> 问：图里是什么？答：一只猫。
<图片2> 问：图里是什么？答：一辆车。
<图片3> 问：图里是什么？答：
```

然后直接回答第三张图，而不是为“猫狗分类”“VQA”“captioning”分别训练一套模型。

Flamingo 的目标就是把这种“语言模型式 prompt 编程”扩展到图文混合场景。

## 核心方法

Flamingo 的关键不是从零训练一个全新的巨型多模态模型，而是把两个已有强项拼起来：一个冻结的视觉编码器负责看图，一个冻结的语言模型负责读上下文和生成文字，中间用可训练的连接模块完成对齐。

### 1. Frozen language model：锁住语言大脑

Frozen language model 指训练 Flamingo 时，原来的语言模型参数不再更新。它已经学会了语言、常识、推理模式和 in-context learning，Flamingo 不希望多模态训练把这些能力冲坏。

可以把它理解成：不要重写一个资深文案的大脑，而是给他装一个可控的视觉输入接口。

这样做有三个好处：

- 保留语言模型原有的生成能力和 few-shot prompting 能力。
- 降低多模态训练的风险，避免视觉数据把语言模型训练“带偏”。
- 工程上更像“复用底座 + 学习适配层”，而不是每次都从头造模型。

代价也很明确：语言模型本身的偏见、幻觉、知识边界不会因为接入视觉就自动消失；视觉信息也只能通过新增模块影响它。

### 2. 视觉编码器：把图片和视频变成特征

视觉编码器负责把图片或视频帧转成一组视觉特征。论文中使用的是预训练并冻结的视觉编码器；它不直接回答问题，而是把画面中的纹理、物体、区域、时序信息编码成模型能处理的向量。

如果输入是图片，视觉编码器输出空间上的视觉特征；如果输入是视频，模型会抽取多帧，再得到带时间维度的视觉特征。

这里的重点是：Flamingo 并不是让语言模型直接“读像素”。它先让视觉模型把像素压成语义特征，再把这些特征送给语言模型。

### 3. Perceiver Resampler：把任意视觉输入压成固定数量的视觉 token

图片和视频有一个麻烦：不同图片尺寸、不同视频长度，会产生数量不固定的视觉特征。语言模型不喜欢这种不稳定的输入规模，因为 cross-attention 的计算成本会随视觉 token 数暴涨。

Perceiver Resampler 的作用就是做一个“视觉信息压缩接口”：

- 输入：视觉编码器产生的大量空间/时间特征。
- 处理：用一组可学习的 latent query 去关注重要视觉信息。
- 输出：固定数量的视觉 token，论文主实验中常用 64 个视觉 token 来表示一张图或一段视频的视觉信息。

产品化地理解，它像一个“视觉摘要器”：不管用户上传一张图、几张图，还是一段短视频，先被整理成语言模型能稳定消费的一小组视觉摘要。

这个设计很重要，因为它把复杂视觉输入变成了稳定 API：语言模型不需要知道原图多大、视频几帧，只需要面对固定形态的视觉 token。

### 4. Gated cross-attention：让语言模型按需看图

仅有视觉 token 还不够，语言模型需要一种机制在生成文字时读取这些视觉 token。Flamingo 的做法是在冻结的语言模型层之间插入新的 GATED XATTN-DENSE 层。

其中 cross-attention 的意思是：文本 token 作为 query，去视觉 token 里取信息。比如模型生成“这张图里有”之后，可以通过 cross-attention 查看图像特征，再决定后面写“狗”“杯子”还是“交通灯”。

gated 的意思是：新增视觉通路不是一开始就强行干预语言模型，而是通过门控系数逐步打开。论文里这类门控初始化接近“关闭”状态，训练初期模型几乎保持原语言模型行为；随着训练推进，模型学会什么时候该依赖视觉信息，什么时候继续依赖语言上下文。

这解决了一个实际工程问题：如果粗暴地把视觉信息塞进语言模型，很容易破坏已经训练好的语言能力。门控 cross-attention 更像给语言模型加一条可调音量的视觉输入通道。

### 5. Few-shot multimodal prompting：用图文示例临时定义任务

Flamingo 的 few-shot multimodal prompting 指的是：推理时在上下文里给少量图文示例，让模型照着模式完成新样本。

例子可以是：

```text
<图片A> Question: What color is the bus? Answer: yellow.
<图片B> Question: What color is the chair? Answer: red.
<图片C> Question: What color is the car? Answer:
```

模型不需要针对“颜色问答”更新参数，而是从上下文中识别出任务格式：看图，回答问题，答案要短。

这和后来的“指令调优视觉聊天模型”不是一回事。Flamingo 证明的是多模态 in-context learning：给示例，模型临时适配任务。它没有把后续 LLaVA、GPT-4V 等模型中更强的对话式指令跟随、复杂 GUI 识别、长链路工具调用能力一并解决。

### 6. 交错图文上下文：不是一张图配一句话，而是网页式混合输入

Flamingo 特别强调 arbitrarily interleaved visual and textual data，也就是任意交错的图文序列。

真实网页不是标准数据集里的“图片 + caption”那么干净。它可能是：

```text
标题
<图片1>
一段解释文字
<图片2>
另一段说明
表格、列表、段落
<图片3>
```

Flamingo 使用包含交错图文网页的大规模数据训练，让模型习惯“图像和文字互相指代”的上下文结构。论文还混合了图文对和视频-文本对数据，用来补充视觉语义对齐和视频理解能力。这个训练形态是它能做 few-shot multimodal prompting 的关键之一：推理时的 prompt 本质上也常常是交错图文。

## 为什么经典

Flamingo 经典，不只是因为榜单效果强，而是因为它把多模态模型的工程路线讲清楚了。

第一，它提出了“冻结强底座 + 训练连接层”的有效范式。视觉模型和语言模型都已经很贵、很强，与其全部重训，不如学习一个跨模态接口。后来的 BLIP-2、OpenFlamingo、IDEFICS 等工作都能看到类似思想。

第二，它把多模态任务从“为每个任务微调模型”推向“用 prompt 定义任务”。这对产品形态影响很大：同一个模型可以通过不同上下文承担 caption、VQA、分类、视频问答等任务，而不是每个功能背后一套专用模型。

第三，它强调交错图文数据的重要性。多模态能力不是只靠静态图文对齐就够了；模型还需要见过真实内容里的图文顺序、引用关系和上下文结构。

第四，它提供了一个稳定的视觉-语言接口设计：视觉编码器负责感知，Perceiver Resampler 负责压缩，gated cross-attention 负责注入，语言模型负责生成。这个分工非常适合产品经理理解多模态系统的模块边界。

## 产品经理启发

1. 多模态产品不是“给文本模型加上传按钮”这么简单。关键要问：视觉信息如何进入模型？以什么粒度进入？会不会压缩掉任务所需细节？Flamingo 的 Perceiver Resampler 就是在回答“视觉输入接口如何稳定化”。

2. few-shot 能力改变了需求交付方式。很多低频、长尾、多格式任务，不一定要先收集大量标注数据再训练专用模型，可以先尝试用图文示例定义任务。但前提是模型真的具备上下文学习能力，而不是只会看图描述。

3. 数据形态会决定产品能力边界。如果产品场景是文档、网页、工单、截图、商品详情页，就不能只关注“图片 + 短 caption”数据；交错图文、上下文引用、前后顺序往往更接近真实使用场景。

4. 冻结底座是一种产品工程策略。它意味着更低的训练风险、更快的迭代、更容易复用已有能力；但也意味着底座缺陷会被继承。产品经理要把“适配层能解决什么”和“底座本身解决不了什么”分开评估。

5. 门控机制对应一种保守的能力接入思路。新能力不要一上来覆盖旧能力，而是可控地注入。这对多模态、工具调用、企业知识接入都类似：新增通道最好能被隔离、观测、逐步放量。

6. 不要把 few-shot prompting 等同于可靠产品交付。论文中的 few-shot 表现说明模型有泛化潜力，但上线产品仍要评估失败模式、提示稳定性、成本、延迟、安全边界和用户是否能构造好示例。

## 局限与争议

1. 模型没有开源，复现成本高。Flamingo 本身来自 DeepMind，训练数据、模型权重和许多工程细节并不完全可复用。后来社区有 OpenFlamingo 等复现，但不能简单等同于原版 Flamingo。

2. 计算和数据门槛很高。它依赖大规模语言模型、大规模视觉编码器、大规模图文/视频数据，以及复杂训练配比。对多数产品团队来说，Flamingo 更像架构启发，而不是可直接照抄的训练方案。

3. few-shot 不等于稳定遵循指令。Flamingo 能根据少量示例适配任务格式，但它不是后来的视觉指令调优助手。不能把“自然语言多轮对话很听话”“能处理复杂操作意图”等能力归功于 Flamingo。

4. 视觉细节可能在压缩中丢失。Perceiver Resampler 把大量视觉特征压成固定数量 token，有利于效率和统一接口，但对小字、密集目标、精细空间关系、复杂图表等任务可能不够。

5. 仍然可能幻觉。语言模型生成式回答天然可能编造，接入视觉后也可能看错、忽略图像证据，或者用语言先验覆盖视觉事实。

6. 评测覆盖有限。论文覆盖了多种图像和视频任务，但真实产品会遇到更长上下文、更复杂文档、更高安全要求、更多 OCR/表格/界面理解场景。论文成绩不能直接推导到所有多模态产品。

## 今天怎么看

今天看 Flamingo，它最重要的遗产不是某个具体榜单，而是“如何把强语言模型接入视觉世界”的系统设计。

仍然重要的部分包括：

- 冻结或半冻结底座，用适配层连接不同模态。
- 把可变视觉输入压缩成固定 token 接口。
- 通过 cross-attention 把视觉信息注入语言生成。
- 用交错图文上下文训练模型，使推理时的多模态 prompt 更自然。
- 把多模态任务产品化为“上下文中的示例与指令”，而不是只依赖任务专用分类头。

已经被后续工作推进或替代的部分包括：

- 指令跟随能力：LLaVA、InstructBLIP、GPT-4V 等后续模型更强调视觉指令调优和对话体验。
- 视觉细节能力：后续模型在 OCR、图表、屏幕理解、文档理解上做了更多专门优化。
- 开源生态：OpenFlamingo、IDEFICS、BLIP-2 等让类似思想更容易被研究和工程团队复用。
- 产品形态：今天的多模态产品通常还会叠加 RAG、工具调用、结构化输出、安全策略和任务评测，而不只是 few-shot prompt。

所以，Flamingo 最适合作为理解现代多模态大模型的一块地基：它解释了为什么“语言模型 + 视觉编码器 + 连接模块 + 交错图文训练”能工作。但它不是今天所有视觉聊天能力的完整答案。

## 理解检查

1. 为什么 Flamingo 要冻结语言模型，而不是直接把语言模型和视觉模型一起全量微调？这样做分别带来什么收益和代价？
2. Perceiver Resampler 解决的是视觉输入中的什么产品/工程问题？如果没有它，图片和视频输入会给语言模型带来哪些麻烦？
3. Gated cross-attention 中的“gated”为什么重要？它和简单地把视觉 token 拼到文本 token 前面有什么不同？
4. Flamingo 的 few-shot multimodal prompting 和后来的视觉指令调优有什么区别？为什么不能把后者的能力误归给 Flamingo？
5. 如果你要做一个“看商品详情页并回答运营问题”的 AI 产品，Flamingo 对数据形态和评估方式有什么启发？
