# DALL-E：Zero-Shot Text-to-Image Generation

> 分类：多模态与视觉语言  
> 年份：2021  
> 论文：https://arxiv.org/abs/2102.12092  
> 状态：reviewed

## 一句话

DALL-E 把“根据一句自然语言生成图片”（text-to-image generation）从专门小模型推向了大规模多模态生成：它先把图片压缩成离散视觉 token，再用类似 GPT 的自回归 Transformer 学习“文本 token 后面应该接什么图像 token”。

## 背景问题

在 DALL-E 之前，文生图已经存在，但更像是一个“受限演示能力”：模型通常在 MS-COCO、CUB 等固定数据集上训练，依赖 GAN、多尺度生成器、注意力模块、额外标注或辅助损失来提升效果。

当时的核心卡点有三类：

- **生成质量不稳定**：图像经常有物体扭曲、前景背景混合、局部细节错乱等问题。
- **泛化能力有限**：模型能生成训练分布里常见的“鸟”“花”“人骑马”，但很难稳定组合新概念，比如“手风琴材质的貘”“穿圣诞毛衣的小刺猬遛狗”。
- **产品入口不自然**：很多方法需要类别、分割、关键点、布局等额外条件；而真实用户更希望直接用一句话表达意图。

DALL-E 的问题意识很像 GPT-3：如果我们不为每个视觉任务单独设计模型，而是把“文本 + 图像”都看成 token 序列，并用大模型、大数据训练，会不会自然出现更通用的生成能力？

## 核心方法

DALL-E 的方法可以拆成两步：先把图像变成“视觉词语”，再让语言模型学习如何续写这些视觉词语。

### 1. Text-to-image generation：把一句话变成图片

Text-to-image generation 指的是：输入一段自然语言描述，输出一张与描述匹配的图片。

关键难点在于，文本到图片不是一一对应关系。“一只红色椅子放在窗边”可以有无数种合理画法：椅子的样式、房间光线、镜头角度、材质、背景都没有被写死。因此模型不只是“翻译”，还要在合理范围内补全大量视觉细节。

产品上，这意味着文生图模型同时在做三件事：

- **理解意图**：识别对象、属性、关系、风格。
- **补全上下文**：决定没被明说但图片需要的细节。
- **生成视觉结果**：把抽象描述落成像素级图像。

### 2. 离散 VAE / dVAE：把图片压缩成视觉 token

Transformer 擅长处理 token 序列，但原始图片是大量像素。直接把 256x256 RGB 图片当成像素序列，会非常长，而且模型会被迫花大量能力预测局部纹理和颜色噪声。

DALL-E 用一个 discrete VAE（dVAE，离散变分自编码器）先压缩图片：

- 输入：一张 256x256 的 RGB 图片。
- 编码：压缩成 32x32 的网格，也就是 1024 个图像 token。
- 每个图像 token：从 8192 个离散代码中选择一个。
- 解码：再由 dVAE decoder 把这些视觉 token 还原成图片。

可以把 dVAE 理解为给图片建立一本“视觉词典”。它不是逐像素描述图片，而是用一串离散代码概括局部视觉块：某种边缘、颜色组合、纹理、局部结构。这样，后面的 Transformer 不需要直接预测每个像素，而是在预测“下一枚视觉词”。

这里的“离散”很重要。普通 VAE 往往把图像编码成连续向量；DALL-E 需要的是可以像文字一样排列、预测、采样的离散 token。离散化让图像进入了语言模型擅长的序列建模框架。

代价也很清楚：压缩会损失高频细节。原论文也指出，dVAE 压缩后图像的主体通常可辨认，但细小文字、毛发纹理、细线条可能丢失或变形。

### 3. Autoregressive Transformer：像 GPT 一样“续写图片”

第二阶段，DALL-E 固定 dVAE，把文本 token 和图像 token 拼成一个序列：

- 最多 256 个 BPE 文本 token。
- 1024 个图像 token。
- 总长度最多 1280 个 token。

然后训练一个 120 亿参数的 decoder-only sparse Transformer，用自回归方式建模这个序列。

Autoregressive（自回归）的意思是：模型每次只预测下一个 token，预测时只能看见前面的 token。生成图片时，它先读入文本 prompt，然后一个接一个地产生 1024 个图像 token，最后由 dVAE decoder 解码成 256x256 图片。

用产品经理能理解的话说：DALL-E 把“画图”改造成了“续写”。文本 prompt 是开头，图片 token 是后续内容。模型学到的是：在大量互联网图文对里，某类文字描述后面通常应该接怎样的视觉结构。

### 4. 文本条件生成：文本不是标签，而是控制界面

DALL-E 的生成是 text-conditioned generation（文本条件生成）：图像 token 的生成过程始终受文本 token 影响。

这和传统分类标签不同。标签通常是单个类别，如“狗”“飞机”；自然语言可以表达组合关系、风格、位置、材质、数量和类比，例如：

- “一个牛油果形状的扶手椅”
- “从低角度拍摄的透明茶壶”
- “一只穿红帽子、黄手套、蓝衬衫的刺猬”

这带来了一个产品层面的范式变化：用户不再需要学习复杂参数面板，而是用语言作为高维控制器。不过，语言控制不等于精确控制。原始 DALL-E 对多对象绑定、数量、空间关系和同义改写都很脆弱。

### 5. Zero-shot 组合泛化：没专门训练，也能组合新概念

论文标题里的 zero-shot 不是说模型没有训练，而是说它在评测任务上没有专门用该任务的数据或标签微调。比如它可以在没有使用 MS-COCO caption 训练标签的情况下，直接根据 COCO 风格 caption 生成图片，并与专门训练过的模型比较。

更重要的是组合泛化：模型可以把训练中见过的概念重新组合到新描述里。例如它可能分别见过“貘”“手风琴”“材质迁移”，但没见过“手风琴材质的貘”。如果它能生成一个大致合理的结果，就说明它学到的不只是类别记忆，而是一定程度的概念组合。

不过这里要控制预期。原始 DALL-E 展示了“有时能组合”，不是“可靠遵循复杂指令”。论文和官方博客都承认：对象越多、属性绑定越复杂，成功率越低；换一种等价说法，也可能导致结果明显变差。

### 6. 生成后重排：不是每次采样都好

DALL-E 会从 Transformer 采样多个候选图像，再用一个预训练的文本-图像对比模型进行 reranking（重排），选择更匹配文本的结果。OpenAI 当时的展示常用“从 512 个候选里选前 32 个”的方式。

这点对产品理解很重要：用户看到的好结果不完全等于底层生成器一次命中的能力。系统层面还包括采样数量、排序模型、展示策略和人工挑选边界。对文生图产品来说，“生成模型 + 评估/筛选模型”往往比单个模型更接近真实产品形态。

## 为什么经典

DALL-E 经典不只是因为它能画图，而是因为它改变了多模态生成的默认想象。

第一，它证明了“语言模型范式”可以跨到视觉生成。只要把图片离散化成 token，就可以用类似 GPT 的方式建模文本和图像的联合分布。这让多模态不再只是“图像分类 + 文本标签”，而是进入“文本控制视觉生成”的阶段。

第二，它把文生图从数据集任务推向开放世界 prompt。之前很多模型是在固定数据集里追指标；DALL-E 强调 zero-shot：用户随便写自然语言，模型尝试组合出没被专门标注过的场景。这非常接近后来生成式 AI 产品的交互形态。

第三，它把“组合能力”摆到台前。文生图最有产品想象力的地方，不是生成一张常见狗照片，而是把概念、风格、材质、空间关系重新组合。DALL-E 让行业看见：大规模图文数据 + 大模型可能学到这种组合接口。

第四，它也预示了后来产品系统的关键部件：大规模图文数据、文本 prompt、候选生成、图文匹配重排、人工评估、偏见与安全风险。这些今天仍然是图像生成产品的底层问题。

## 产品经理启发

1. **把自然语言当成产品控制层，而不只是搜索框。** DALL-E 的启发是：语言可以承载对象、属性、关系、风格、约束和意图。设计 AI 产品时，不必急着把所有控制都拆成表单；可以让语言承担开放表达，再用必要控件补充确定性。

2. **区分“会生成”和“可控可交付”。** 原始 DALL-E 能展示惊艳样例，但在数量、文字、空间关系、细节一致性上不稳定。产品验收不能只看最佳样例，要看用户常见 prompt 下的稳定率、失败模式和可修正性。

3. **组合泛化比单点能力更重要。** 对 AI 产品来说，模型是否会“画猫”不稀缺；稀缺的是能否把猫、材质、姿态、品牌调性、构图约束组合起来。需求评估应覆盖组合案例，而不是只测单个名词。

4. **生成产品通常需要筛选层。** DALL-E 的重排说明，产品体验不是“模型吐一张图”那么简单。候选数量、排序模型、相似度评估、安全过滤、用户挑选 UI，都会决定最终可用性和成本。

5. **数据策略决定能力边界。** DALL-E 依赖 2.5 亿互联网图文对。开放世界能力来自大规模弱标注数据，但也带来噪声、偏见、版权、隐私和品牌安全问题。PM 不能只问“模型多大”，还要问“数据从哪里来、覆盖什么、排除了什么、风险如何治理”。

6. **不要把演示能力误判为工作流能力。** 原始 DALL-E 的核心是 text-to-image generation，不具备后来的局部编辑、inpainting、精确改图能力（这些属于 DALL-E 2 及扩散模型路线）。面向真实生产流程时，需要拆分：首图生成、局部编辑、一致性、版本管理、版权安全、团队协作，各自可能需要不同能力。

## 局限与争议

- **分辨率和细节有限。** 原始 DALL-E 生成的是 256x256 图像；dVAE 压缩会损失细小文字、纹理和线条。不要把 DALL-E 2/3 或后续模型的高清、精修能力归给它。
- **复杂绑定不稳定。** 多对象、多属性、多空间关系容易混淆，例如颜色和对象错配、数量不准、位置关系不可靠。
- **prompt 表达脆弱。** 语义等价的改写可能导致成功率变化。这说明模型还没有真正达到可预测的语言控制。
- **专业小分布表现较弱。** 论文中模型在 CUB 鸟类数据集上明显不如专门训练的方法，说明开放世界模型未必自动胜过垂直领域模型。
- **候选重排抬高了展示质量。** 多次采样加重排可以显著改善结果，但也增加成本，并掩盖单次生成的失败率。
- **数据与社会风险突出。** 使用大规模互联网图文对会继承偏见、刻板印象、不良内容和版权争议。论文提出了社会影响问题，但原始 DALL-E 不是一套完整的安全产品方案。
- **计算门槛高。** 120 亿参数、海量数据和大规模分布式训练让这种路线很难被普通团队复现。

## 今天怎么看

今天看，原始 DALL-E 的具体架构已经不是主流文生图产品的唯一答案，甚至不是高保真图片生成的主路线。2022 年后，DALL-E 2、Imagen、Stable Diffusion 等扩散模型路线快速成为主流：它们通常从噪声出发，通过多步 denoising 逐渐生成图像，或者在 latent space 中扩散，再解码成图片。

和原始 DALL-E 的差异可以这样理解：

- **DALL-E 1 路线**：把图片压缩成离散 token，然后像语言模型一样从左到右预测 token。优点是统一、直观、和 Transformer/GPT 范式高度兼容；缺点是生成长序列成本高，细节受离散压缩影响，局部控制不天然方便。
- **扩散模型路线**：从随机噪声开始，反复去噪，让图像逐渐成形。优点是视觉质量、纹理细节、图像编辑和条件控制通常更强；缺点是采样多步、系统复杂，早期推理速度和成本压力更明显。
- **后来的统一多模态路线**：又重新重视 token 化、Transformer、图像与文本的统一建模，但会结合更强的视觉编码器、扩散/自回归/掩码生成等混合策略。

所以，DALL-E 1 今天最值得学的不是“照着复刻这个架构”，而是三条长期有效的产品判断：

- 自然语言会成为多模态产品的核心控制界面。
- 大规模弱标注图文数据可以带来开放世界组合能力。
- 生成式 AI 的真实体验来自系统：生成、排序、过滤、编辑、评估和用户反馈缺一不可。

也要明确边界：原始 DALL-E 不是 DALL-E 2/3。它没有后续模型的高分辨率真实感、强编辑能力、复杂指令遵循和商业化安全系统。把它放在历史位置上，它是“证明语言可以驱动开放视觉生成”的关键节点，而不是今天所有文生图能力的完整来源。

## 理解检查

1. 为什么 DALL-E 不直接让 Transformer 预测 256x256 图片的每个像素，而要先用 dVAE 把图片变成 32x32 的离散 token？

<details>
<summary>参考要点（先自己答，再展开）</summary>

- 256x256 RGB 图片直接展开为像素序列过长，Transformer 建模成本极高
- dVAE 把图片压缩成 1024 个离散 token，让 Transformer 预测”视觉词”而非逐像素
- 离散化让图像进入语言模型擅长的 token 序列框架，代价是压缩会损失高频细节

</details>

2. “文本条件生成”和”用类别标签生成图片”有什么本质区别？这种区别为什么对产品交互重要？

<details>
<summary>参考要点（先自己答，再展开）</summary>

- 类别标签只能表达预定义类别；自然语言可以表达组合关系、材质、风格、数量、位置等复合属性
- 用户无需学习参数面板，直接用语言表达意图，降低了表达复杂需求的门槛
- 但语言控制不等于精确控制，多对象绑定、数量、空间关系在原始 DALL-E 里仍不稳定

</details>

3. DALL-E 标题里的 zero-shot 指什么？它和”模型没训练过”是不是一回事？

<details>
<summary>参考要点（先自己答，再展开）</summary>

- zero-shot 指在评测任务上没有用该任务的数据或标签专门微调，不是说模型完全没训练
- 模型已在 2.5 亿互联网图文对上大规模预训练，具备开放世界的概念组合能力
- 其核心意义在于组合泛化：把训练中见过的概念重新组合到未被专门标注的新描述

</details>

4. 为什么说 DALL-E 的组合泛化很有启发，但又不能把它理解成可靠的复杂指令遵循？

<details>
<summary>参考要点（先自己答，再展开）</summary>

- 组合泛化指模型能把分别见过的概念重新组合，展示了大规模数据带来的创造性
- 但对象越多、属性绑定越复杂，成功率越低；换等价说法也可能导致结果明显变差
- prompt 表达脆弱，说明模型还没达到可预测的语言控制，不能当可靠产品指令界面

</details>

5. 原始 DALL-E 的自回归 token 生成路线，和后来扩散模型路线在生成方式、优势和产品边界上有什么差异？

<details>
<summary>参考要点（先自己答，再展开）</summary>

- DALL-E 1 从左到右预测离散 token，与 GPT 范式统一，但长序列生成成本高、细节受离散压缩影响
- 扩散模型从随机噪声反复去噪，视觉质量、纹理细节和图像编辑通常更强
- 原始 DALL-E 不具备 DALL-E 2/3 或 Stable Diffusion 的高分辨率、强编辑能力和局部控制

</details>

## 延伸阅读

- 原论文：Aditya Ramesh et al., [Zero-Shot Text-to-Image Generation](https://arxiv.org/abs/2102.12092), 2021。
- OpenAI 介绍：[DALL·E: Creating images from text](https://openai.com/blog/dall-e/)，注意这是原始 DALL-E，不是 DALL-E 2/3。
- 相关基础：van den Oord et al., [Neural Discrete Representation Learning](https://arxiv.org/abs/1711.00937)，VQ-VAE，把连续图像表示离散化的代表工作。
- 相关基础：Razavi et al., [Generating Diverse High-Fidelity Images with VQ-VAE-2](https://arxiv.org/abs/1906.00446)，离散视觉 token 与高质量图像生成的重要前序工作。
- 同期多模态理解：Radford et al., [Learning Transferable Visual Models From Natural Language Supervision](https://arxiv.org/abs/2103.00020)，CLIP，理解 DALL-E 重排和图文对齐生态很有帮助。
- 后续路线：Ramesh et al., [Hierarchical Text-Conditional Image Generation with CLIP Latents](https://arxiv.org/abs/2204.06125)，DALL-E 2，已转向 CLIP latent 与扩散模型组合。
- 后续路线：Rombach et al., [High-Resolution Image Synthesis with Latent Diffusion Models](https://arxiv.org/abs/2112.10752)，理解 Stable Diffusion 等 latent diffusion 产品路线的关键论文。
- 后续路线：Yu et al., [Scaling Autoregressive Models for Content-Rich Text-to-Image Generation](https://arxiv.org/abs/2206.10789)，Parti，展示自回归路线在 DALL-E 之后仍有延续。
