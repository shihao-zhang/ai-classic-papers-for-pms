# BERT：BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding

> 分类：自然语言处理  
> 年份：2018  
> 论文：https://arxiv.org/abs/1810.04805  
> 状态：draft

## 一句话

BERT 把 Transformer 的 encoder 训练成一个“能同时看左边和右边上下文”的通用语言理解底座，让很多 NLP 任务从“为每个任务单独设计模型”转向“先大规模预训练，再用少量标注数据微调”。

## 背景问题

在 BERT 之前，NLP 已经知道“预训练表示”有用，但仍有几个明显卡点：

1. **词向量太静态**：传统 word embedding 里，“bank”无论在“river bank”还是“bank account”里向量都差不多；模型很难天然理解同一个词在不同上下文里的不同含义。
2. **很多系统依赖任务专用结构**：问答、情感分类、实体识别、句子关系判断往往各做一套架构，产品化时意味着更多模型、更多维护成本、更多数据需求。
3. **单向语言模型不适合所有理解任务**：GPT-1 这类 left-to-right 模型从左往右预测下一个词，适合生成，但在阅读理解、实体识别这类任务里，一个词的含义常常同时依赖前文和后文。
4. **浅层双向不等于深层双向**：ELMo 等方法会把左到右和右到左两个模型的结果拼起来，但两个方向不是在每一层都充分交互；BERT 想让模型的每一层都融合左右上下文。

所以，BERT 要解决的不是“让机器会写文章”，而是“让机器获得更强、更通用的语言理解表示”。

## 核心方法

BERT 的核心可以拆成五件事。

1. **Bidirectional encoder：用 Transformer encoder 做深度双向理解**

Transformer 有 encoder 和 decoder 两种典型用法。BERT 采用的是 encoder：输入一整段文本后，里面每个 token 都可以通过 self-attention 关注同一句话里的其他 token。关键点是“双向”：模型在理解某个词时，不只看它左边已经出现的词，也看右边的词。

这和 GPT 路线不同。GPT 使用 decoder 风格的因果注意力，每个 token 只能看左侧历史，因为它的目标是预测下一个 token。这种约束对生成很自然：写字时不能偷看未来。但对理解任务，尤其是命名实体识别、抽取式问答、句子关系判断，能同时看前后文通常更合适。

2. **MLM：把一部分词遮住，让模型根据上下文猜回来**

如果模型可以看完整句子，直接预测每个词会作弊：它已经看见了答案。BERT 的解决办法是 Masked Language Modeling, MLM。

训练时随机选取一部分 token，让模型根据周围上下文预测原始 token。直观地说，就是做“完形填空”：

> 用户在 [MASK] 上订了一张去上海的票。

模型要结合左右两边，判断 `[MASK]` 可能是“网站”“App”“平台”等。论文中常用的训练配方是随机选择 15% 的 WordPiece token 作为预测目标，其中多数替换成 `[MASK]`，少数替换成随机词或保持不变，以减轻预训练和微调阶段的输入差异。

MLM 的产品意义是：模型学到的不是“下一个词是什么”，而是“这个位置在当前语境下应该表达什么”。这就是上下文表示的来源。

3. **NSP：让模型判断两段文本是否相邻**

BERT 还加入了 Next Sentence Prediction, NSP。训练样本由句子 A 和句子 B 组成：一半时候 B 真的是 A 的下一句，另一半时候 B 是随机句子。模型通过 `[CLS]` 位置的表示来判断二者是否连续。

作者加入 NSP 的动机是服务句子对任务，比如自然语言推理、问答、语义匹配。很多产品问题也长得像句子对：用户问题和候选答案是否匹配、搜索 query 和文档片段是否相关、合同条款和风险描述是否对应。

但要注意，NSP 后来成为争议点。RoBERTa 等后续工作表明，去掉 NSP、扩大数据和训练步数、优化 batch 与 mask 策略，也能取得更强效果。因此今天看，BERT 的“MLM + encoder 表示”比“必须使用 NSP”更经得住时间考验。

4. **Pretrain + finetune：先学通用语言，再适配具体任务**

BERT 的训练分两步：

- **Pre-training**：用大规模无标注文本训练 MLM 和 NSP，让模型学到通用语言规律。
- **Fine-tuning**：针对具体任务加一个很薄的输出层，用标注数据端到端微调全部参数。

这套流程改变了 NLP 工程路线。以前常见做法是为每个任务设计模型；BERT 之后，很多任务可以共用同一个预训练底座，只在输入格式、输出头和标注数据上做适配。

对产品经理来说，这意味着“能力建设”从单点项目变成平台资产：一个强底座可以被分类、抽取、匹配、问答等多个产品场景复用。

5. **上下文表示：同一个词在不同语境里得到不同向量**

BERT 输出的不是固定词典解释，而是 contextual representations。每个 token 的向量都由当前整段输入共同决定。

例如“苹果发布了新手机”和“我吃了一个苹果”里的“苹果”，在 BERT 里会因为上下文不同而得到不同表示。这个能力对产品很关键：模型不是只匹配关键词，而是在判断“这个词在这句话里扮演什么角色”。

## 为什么经典

BERT 经典，不只是因为榜单分数高，而是因为它把几条路线合在一起，形成了后来几年 NLP 的默认范式。

1. **证明深度双向预训练非常有效**：论文在 GLUE、SQuAD 等 11 个 NLP 任务上刷新结果，说明 encoder-only 的双向理解模型可以成为通用语言理解底座。
2. **让微调成为主流工程范式**：BERT 让“下载预训练模型，加任务头，少量标注微调”变成自然语言理解任务的标准流程。
3. **降低任务专用模型的重要性**：很多过去需要复杂结构的任务，可以被统一成“输入文本或文本对，输出分类、span 或 token 标签”。
4. **推动模型生态开放**：Google 发布代码和预训练模型后，BERT 很快被复现、压缩、蒸馏、迁移到多语言和行业语料，成为搜索、客服、风控、内容理解等场景的基础组件。
5. **为后续 encoder 系列奠基**：RoBERTa、ALBERT、DistilBERT、Sentence-BERT 等都可以看作对 BERT 的训练、效率、句向量或部署形态的继续改造。

## 产品经理启发

1. **先判断任务是“理解”还是“生成”**

BERT 更适合分类、匹配、抽取、排序、实体识别、语义检索等理解型任务；GPT 更适合生成、续写、对话、复杂指令执行。今天的大模型产品常把两者结合：用 embedding 或 reranker 做召回和排序，用生成模型做回答和交互。

2. **把“模型能力”设计成可复用资产**

BERT 的价值在于一个底座服务多个任务。做 AI 产品时，不要只问“这个需求要训练一个什么模型”，还要问“这个能力能否沉淀成统一的文本理解层，复用到搜索、推荐、审核、客服、知识库等场景”。

3. **数据策略要区分无标注预训练和有标注微调**

BERT 提醒我们：无标注文本可以学习语言常识和领域表达，标注数据则负责把能力对准业务目标。对 PM 来说，数据规划不只是“攒标签”，还包括收集高质量领域语料、定义输入格式、设计任务标签和评估集。

4. **微调不是魔法，任务定义仍然决定上限**

同一个 BERT，可以做情感分类、问答抽取、相似度匹配，但每个任务的输入输出形式不同。产品经理需要把模糊需求拆成模型能学习的任务：是判断关系、找答案片段、给 token 打标签，还是给候选结果排序。

5. **评估要贴近产品风险**

BERT 论文用 GLUE、SQuAD 等 benchmark 证明通用性。落到产品里，benchmark 只能证明方向，不能替代业务评估。比如客服问答要看误答率和转人工率，内容审核要看漏放与误杀，搜索排序要看点击、满意度和长尾 query。

## 局限与争议

1. **不是生成式模型**

BERT 的训练目标不是从左到右生成文本，所以它不能像 GPT 那样天然写长文、对话或连续推理式输出。它更像“阅读理解器”，不是“写作者”。

2. **NSP 的必要性后来被质疑**

论文认为 NSP 有助于句子关系任务，但后续 RoBERTa 等工作显示，训练更充分、数据更多、mask 策略更好时，去掉 NSP 也可以更强。这说明 BERT 的成功不应简单归因于 NSP。

3. **预训练和微调存在输入不一致**

MLM 训练中出现 `[MASK]`，但真实下游任务通常不会出现这个 token。论文用 80/10/10 的替换策略缓解，但这个 mismatch 仍是设计上的折中。

4. **微调可能不稳定，尤其是小数据任务**

BERT 论文也提到大模型在小数据任务上可能需要多次随机重启选择较好结果。产品上如果标注量小、类别边界模糊，微调效果可能波动明显。

5. **上下文窗口和计算成本有限制**

原始 BERT 常用最大长度 512 token。长文档理解需要切片、检索、层级建模或更长上下文模型。对合同、研报、医疗记录这类长文本产品，不能把“用了 BERT”直接等同于“理解整篇文档”。

6. **语言理解不等于事实可信**

BERT 能学到强表示，但不保证有最新事实、因果推理或可解释依据。它适合做语义判断，不适合单独承担高风险决策。

## 今天怎么看

今天看 BERT，需要同时看到它的历史地位和产品边界。

仍然重要的部分：

- **上下文表示**仍是现代 NLP 的基本思想：词的含义由上下文决定。
- **预训练 + 适配**仍是大模型时代的核心范式，只是适配方式从 full fine-tuning 扩展到 prompt、instruction tuning、LoRA、adapter、RAG 等。
- **encoder 在理解任务里仍有价值**：在语义检索、rerank、分类、抽取、审核、轻量部署等场景，encoder 或 encoder-like 模型常常比大生成模型更便宜、更快、更容易控。
- **统一输入输出思想仍然有产品价值**：把不同业务问题规整成少数几类模型任务，是 AI 产品设计的重要能力。

已经被后续路线部分替代的部分：

- 如果目标是自然语言交互、长文本生成、工具调用和复杂任务执行，GPT 类 decoder-only 大模型已经成为更常见的产品底座。
- 原始 BERT 的训练配方不再是最优答案，RoBERTa 等工作改进了训练方式，DistilBERT 等工作优化了部署效率。
- 原始 fine-tuning 不是唯一适配方式。今天很多产品更倾向先用通用大模型、embedding、reranker、RAG 和少量参数适配组合出系统能力。

一句话总结今天的定位：BERT 是“理解型 AI 产品”的经典起点，GPT 是“生成与交互型 AI 产品”的主线起点；二者不是谁完全取代谁，而是服务不同产品环节。

## 理解检查

1. 为什么 BERT 可以同时看左右上下文，而 GPT 的预训练通常不能看未来 token？这个差异分别适合什么产品任务？
2. MLM 为什么能避免“双向模型直接看见答案”的问题？它又带来了什么预训练和微调不一致？
3. NSP 最初想解决什么问题？为什么后续工作会质疑它的必要性？
4. 如果你要做一个企业知识库问答系统，哪些环节更适合 BERT 类 encoder，哪些环节更适合 GPT 类生成模型？
5. “上下文表示”为什么比静态词向量更适合处理多义词、实体识别和语义匹配？
