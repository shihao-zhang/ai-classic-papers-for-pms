# ViT：An Image is Worth 16x16 Words

> 分类：视觉 Transformer 与自监督  
> 年份：2020  
> 论文：https://arxiv.org/abs/2010.11929  
> 状态：draft

## 一句话

ViT 证明了：只要有足够大规模的数据和预训练，可以把图像切成 patch tokens、直接用标准 Transformer encoder 做视觉识别，不必再把 CNN 当成视觉的默认骨干；它让图像和文本第一次真正共享同一套建模语言（token、attention、pretraining、scaling），为后来的 CLIP、MAE、多模态大模型铺好了视觉底座。

## 背景问题

Transformer 在 NLP 里已经证明了两件事：擅长大规模并行训练，且效果会随着数据和参数持续变好。但在 2020 年前后，计算机视觉的主干仍然牢牢是 CNN。

CNN 之所以强，是因为它天生带了一批针对图像的“先验假设”（inductive bias）：

- 局部连接：相邻像素更相关，卷积核只看局部窗口。
- 权重共享与平移等变性：同一个特征检测器在图像各处复用，物体平移后仍能被识别。
- 层级结构：从边缘、纹理到部件、物体，逐层抽象，天然多尺度。

这些先验等于提前把“图像应该怎么看”写进了架构，所以 CNN 在中小规模数据上就能训得又快又稳。

但这也带来一个被长期搁置的问题：这些手工先验，到底是图像任务的**必需品**，还是只是数据不够多时的**拐杖**？NLP 那边已经给出一个信号——当数据足够大，通用的 Transformer 可以靠数据自己学到结构，不需要太多人工先验。ViT 的问题意识正是把这个赌注押到视觉上：**在足够大的数据和算力下，通用架构能不能吞掉视觉专用先验？**

## 核心方法

ViT 的设计哲学是“尽量不改 Transformer”。它没有发明新的注意力机制，而是想办法把图像“翻译”成 Transformer 能直接吃的 token 序列，然后几乎原样套用 NLP 里的标准 encoder。

### 1. Patch 化：把图像变成一串“视觉单词”

ViT 把整张图像切成固定大小的方块 patch（论文主版本用 16×16）。每个 patch 拉平成一个向量，再通过一个线性投影变成 token embedding。论文标题里的“16×16 Words”就是这个类比：一个图像 patch，对 Transformer 来说就像一句话里的一个 word token。

这一步是整个方法的关键转译。一张 224×224 的图被切成几百个 patch token 后，二维网格就变成了一维序列，后面就能完全复用 NLP 的那套机器。代价是 patch 内部的细节被压进了一个向量，patch 的大小直接决定了“分辨率与序列长度”的权衡：patch 越小，token 越多、细节越足，但计算成本也越高。

### 2. Position embedding：把丢掉的空间位置补回来

self-attention 本身是“无序”的——它把输入当成一袋 token，不知道谁在左上、谁在右下。但图像的空间位置显然重要。ViT 因此给每个 patch token 加上一个可学习的位置编码。

一个值得注意的细节：作者试过让位置编码显式感知二维网格（2D-aware），结果发现和简单的 1D 可学习位置编码差别不大。这本身就是 ViT 的态度——尽量少塞人工先验，让模型从数据里自己把空间关系学出来。

### 3. [CLS] token：借 BERT 的“汇总位”做分类

ViT 在 patch 序列最前面额外拼一个可学习的 classification token，思路直接来自 BERT 的 `[CLS]`。它本身不对应任何图像内容，但在经过多层 attention 后，会不断从所有 patch 里汇聚全局信息，最后用它的输出向量接一个分类头出结果。

这是一个“占位汇总”技巧：与其对所有 patch 输出做某种池化，不如专门留一个 token 去学“如何概括整张图”。（后续工作发现，改用全局平均池化、配合调整学习率，效果也相当——说明 `[CLS]` 不是唯一解，而是一个干净的默认选择。）

### 4. 标准 encoder + 大规模预训练：方法简单，胜负手在数据

把 patch token 加上位置编码、拼上 `[CLS]`，剩下的就是一摞标准 Transformer encoder block（multi-head self-attention + 前馈层），和 NLP 几乎一样。

ViT 真正的核心发现不在结构，而在**数据规模决定成败**：

- 如果只在中等规模数据（如 ImageNet-1k）上从零训练，缺少 CNN 先验的 ViT 往往打不过同量级的强 CNN——因为它得从数据里把“局部性、平移等变”这些 CNN 免费自带的东西重新学一遍。
- 一旦换上超大规模预训练（如 ImageNet-21k、JFT-300M）再迁移，ViT 就能追平甚至超过最强 CNN。

换句话说，ViT 不是“天生更强”，而是“先验更少、上限更高、但更吃数据”。论文还给了一个 hybrid 变体：先用 CNN 提特征图、再把特征图当 patch 喂给 Transformer，作为纯 ViT 和纯 CNN 之间的过渡形态。

需要澄清一点：原始 ViT 主要是**监督预训练 + 分类微调**，不是自监督论文（它只附带了一个很初步的掩码 patch 预测实验）。真正把 ViT 推向自监督视觉表示的，是后来的 MAE、DINO、BEiT 等工作——这些贡献不能回算到 ViT 头上。

## 为什么经典

第一，它打破了“视觉必须用 CNN”的默认假设。在 ViT 之前，CNN 是视觉骨干的近乎唯一答案；ViT 证明了在大数据条件下，通用架构可以不靠手工视觉先验也能赢。

第二，它统一了视觉和语言的建模语言。图像一旦被 token 化，attention、position embedding、pretraining、scaling law 这套词汇就能跨模态通用。这是后来 CLIP、Flamingo、LLaVA、GPT-4V 这类视觉-语言模型能顺畅拼接的前提——图像 token 和文本 token 终于能在同一个 attention 里对话。

第三，它把“规模”正式变成视觉架构的一等变量。ViT 用一条清晰的曲线说明：数据越大，通用架构相对专用架构的优势越明显。这把视觉也拉进了基础模型（foundation model）的叙事。

第四，它成了视觉预训练的通用底座。MAE、DINO、CLIP image encoder、SAM 等大量后续工作，都选 ViT 而不是 CNN 作为 backbone——因为它更容易扩展、更容易和多模态对接。

## 产品经理启发

1. **架构选型本质是“数据规模 × 先验”的权衡，不是比谁名字新。** 小数据场景，带强先验的 CNN 往往更稳、更省样本；大数据场景，通用可扩展架构上限更高。PM 评估一个视觉方案时，第一个该问的不是“用了什么架构”，而是“你有多少数据、多少算力来喂它”。

2. **统一表示能显著降低跨模态集成成本。** ViT 把图像变成 token 序列后，“看图说话”“图文检索”“视觉问答”这些能力更容易共用一套底座，而不是每个模态各搭一套烟囱。做多模态产品时，选 token 化、可对接的视觉编码器，长期集成成本更低。

3. **要区分“一个任务模型”和“一个可复用底座”。** ViT 本身只是分类模型，但它预训练出的表示能迁移到检测、分割、检索、多模态。PM 做技术规划时，应优先投资能被多个产品线复用的底座，而不是一次性的单任务模型。

4. **“先验更少”是有账单的。** 通用架构换来的更高上限，是用更多数据、更多算力、更精细的正则化和训练技巧换来的。看到“通用、可扩展”别只看光鲜的一面，要把数据采集、标注、训练成本一起算进 ROI。

5. **预训练数据就是产品风险的一部分。** ViT 的能力高度依赖大规模预训练语料，而语料的来源、版权、偏差、合规会直接进入模型行为，成为下游产品的法律与品牌风险。视觉底座的“数据出身”要在选型阶段就尽调，而不是上线后救火。

6. **分辨率不是免费调大的旋钮。** patch 数随分辨率上升而增加，attention 成本随之变高。产品上要支持高清图、医疗影像、文档大图时，得提前想清楚是换窗口/层级注意力，还是切图、降采样，平衡精度、延迟和成本。

## 局限与争议

第一，ViT 对数据规模高度敏感。在中小数据上从零训练，往往不如同量级 CNN 稳定——它省掉的先验，最终都得用数据补回来。对没有大规模数据或大厂预训练权重的团队，这是现实门槛。

第二，原始 ViT 主要面向图像分类，并不直接解决检测、分割、多尺度密集预测这些任务。Swin Transformer、DETR、Mask2Former 等后续工作才把它扩展到这些场景——这些是别人的贡献，不应记在 ViT 账上。

第三，计算成本随分辨率快速上升。token 数随分辨率增加，标准 self-attention 又是序列长度的平方复杂度，高分辨率视觉任务因此很贵，催生了窗口 attention、层级结构等一系列效率改造。

第四，可解释性并没有因为换成 attention 就变好。attention 权重能看出模型“关注了哪些 patch”，但和 CNN 的特征可视化一样，不能直接当成“模型为什么这么判断”的因果解释。

第五，ViT 不是自监督方法，也不是多模态方法。它是一个监督分类骨干。把视觉自监督、图文对齐这些能力归功于 ViT，是常见的张冠李戴——那些是 MAE、DINO、CLIP 等后续工作的贡献。

第六，它的成功强化了“规模即正义”的路线，也抬高了门槛。ViT 让大数据大算力的视觉路线跑通，客观上把视觉基础模型的研发集中到了少数有数据和算力的玩家手里。

## 今天怎么看

今天 ViT 已经是视觉基础模型最主流的骨干之一。它没有在所有场景取代 CNN（轻量、小数据、端侧场景里 CNN 仍很能打），但它彻底改变了视觉模型的“默认语言”。读 ViT 的价值不在记住 patch size，而在理解一次范式切换：当数据和算力足够大，通用架构可以吞掉领域专用先验，并让跨模态产品更容易统一在一套底座上。

仍然重要的部分：

- patch 化作为“把图像翻译成 token 序列”的通用接口；
- “先验更少、上限更高、但更吃数据”这条权衡曲线；
- 图像 token 化打开的视觉-语言统一建模路径；
- 把视觉正式纳入 scaling（数据/参数/算力越大越强）的叙事。

已经被后续工作改造或替代的部分：

- 纯全局 attention 在高分辨率场景常被 Swin 等窗口/层级注意力替代；
- 原始 1D 可学习位置编码在很多变体中被改进；
- `[CLS]` 汇总被全局平均池化等方案平替；
- 监督预训练被 MAE、DINO、CLIP 等自监督/弱监督路线大幅超越和扩展。

## 理解检查

1. ViT 为什么要先把图像切成 patch tokens？这一步用什么换什么（收益和代价各是什么）？

<details>
<summary>参考要点（先自己答，再展开）</summary>

- 把二维图像转成一维 token 序列，标准 Transformer 才能直接处理。
- 收益：复用 NLP 那套机器——attention、位置编码、预训练、scaling，并为多模态对接铺路。
- 代价：patch 内部细节被压进单个向量；patch 大小决定“分辨率 vs 序列长度/成本”的权衡。

</details>

2. CNN 的 inductive bias 具体指哪些？为什么它们在小数据上是优势、在大数据上反而可能成为上限的束缚？请结合“ViT 在 ImageNet-1k 上不占优、换 JFT 预训练后反超”来解释。

<details>
<summary>参考要点（先自己答，再展开）</summary>

- CNN 先验：局部连接、权重共享/平移等变、层级多尺度结构。
- 小数据：先验等于免费且正确的假设，省样本、训得稳，所以 ImageNet-1k 上 CNN 占优。
- 大数据：先验变成封顶的约束，ViT 能从海量数据自己学到更灵活的结构，所以 JFT 预训练后反超。
- 一句话：先验更少 → 更吃数据 → 上限更高。

</details>

3. ViT 与 MAE、CLIP 三者的关系是什么？哪些贡献属于 ViT，哪些必须归给后续工作？为什么把它们混为一谈是常见错误？

<details>
<summary>参考要点（先自己答，再展开）</summary>

- ViT：提供 token 化的视觉 backbone（原始设定是监督预训练 + 分类）。
- MAE：在 ViT 之上做掩码自监督预训练，贡献是“自监督”，不是 ViT 的。
- CLIP：用图文对比学习做跨模态对齐，贡献是“弱监督多模态”，可以用 ViT 当图像编码器。
- 常见错误：把自监督、多模态能力回算给 ViT；ViT 只是骨干，不是这些范式本身。

</details>

4. 如果一个产品要把图像接进语言模型做视觉问答，ViT 式的 token 化为什么比传统 CNN 特征更方便？请说出至少两个具体好处。

<details>
<summary>参考要点（先自己答，再展开）</summary>

- 图像 token 和文本 token 同构，能直接进同一个 attention 做跨模态对话。
- 共享 Transformer 生态：位置编码、预训练范式、可扩展性一套通用。
- 集成成本低：不必为视觉单独搭一套烟囱，多模态拼接更顺。

</details>

5. 同样是“数据不够”的情况，为什么有人选择直接用大厂 ViT 预训练权重微调，而不是从零训练 ViT？这背后反映了什么选型原则？

<details>
<summary>参考要点（先自己答，再展开）</summary>

- ViT 从零训练吃大数据，小数据上不稳、往往打不过 CNN。
- 用大厂预训练权重，等于把“大规模数据/算力”的成果迁移过来，微调即可。
- 选型原则：缺数据时优先复用预训练底座，而不是从零造，把别人的规模红利变成自己的起点。

</details>
