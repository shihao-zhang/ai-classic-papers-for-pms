# LAION-5B：LAION-5B: An Open Large-Scale Dataset for Training Next Generation Image-Text Models

> 分类：数据集与数据治理  
> 年份：2022  
> 论文：https://arxiv.org/abs/2210.08402  
> 状态：draft

## 一句话

LAION-5B 把约 58.5 亿对「图片 + 文字描述」从公开网络里捞出来、用 CLIP 模型过滤一遍后开源放出，第一次让任何人都能拿到「网络规模」的图文数据去训练 CLIP、Stable Diffusion 这类模型；它既点燃了开源多模态/文生图的爆发，也成了一个绕不开的反面教材——把整个开放网络当训练集，意味着把网络里的偏见、版权争议、NSFW 乃至非法内容一起继承下来，让「数据治理」第一次被摆到所有人面前。

## 背景问题

到 2021、2022 年，业界已经清楚：CLIP（图文对比学习）、文生图这类模型的能力，极度依赖**海量的图文配对数据**——也就是「一张图 + 一句描述它的文字」这种成对样本，规模动辄要数亿、数十亿。

但这种数据当时几乎被少数大公司垄断在内部。OpenAI 训 CLIP 用的是自建的、未公开的 4 亿图文对；Google 也有自己内部的大规模图文集。**外面的研究者和开源社区根本拿不到同等规模的数据**，于是即便知道方法、有算力，也复现不出 CLIP、做不出有竞争力的文生图模型。能力被「数据的不可得」卡住了。

更深一层的问题是：人工标注这种规模的数据完全不现实（几十亿张图，没法靠人一条条写描述）。唯一可行的来源是**开放网络**——网页里的图片天然带着 alt 文本、标题、周边文字，这就是现成的「图 + 描述」。但网络数据又脏又杂：描述和图常常对不上，混着大量垃圾、广告、不良内容。所以真正的难题是：**怎么从又大又脏的开放网络里，自动筛出足够干净、足够对齐的图文对，并且把它合法、可用地开放出来？**

## 核心方法

LAION-5B 的做法可以拆成「捞、滤、放」三步，技术上不复杂，关键在于规模和工程化。

### 1. 捞：从 Common Crawl 抽图文对

它的原料是 **Common Crawl**——一个公开的、对整个网络做大规模抓取的网页存档。LAION 从这些网页的 HTML 里，把 `<img>` 标签的图片地址和它对应的 **alt 文本**（网页给图片写的替代文字描述）成对提取出来。这就得到了海量的「图片 URL + 文字描述」候选对，但此时极脏：很多描述和图片根本不匹配。

### 2. 滤：用 CLIP 给「图文是否匹配」打分

这是整个工作的核心招数，叫 **CLIP 过滤（CLIP filtering）**。CLIP 能把图片和文字各自编码成向量，并衡量两者的语义相似度。LAION 用一个现成的 CLIP 模型，给每一对「图 + 描述」计算图像向量和文本向量的相似度，**只保留相似度高于某个阈值的对**（英文部分用的阈值约 0.28），把那些「图文对不上」的噪声样本扔掉。

这里有个值得记住的思路：**用一个已有的模型，来给训练下一代模型的数据做清洗。** 它高效、可规模化，但也埋了隐患——后面会讲。

最终筛出约 58.5 亿对，并按语言切分（约 23 亿英文、约 22 亿其他语言、约 13 亿语言未定），所以它是个**多语言**数据集。除了图文对，LAION 还给每条样本附上一批元数据：CLIP 相似度、**NSFW 不良内容评分**、水印概率、以及单独的「美学评分」子集（LAION-Aesthetics，挑出更好看的图，对训练文生图很有用）。

### 3. 放：只发 URL 和元数据，不发图片本身

LAION-5B **没有直接打包分发图片**，而是发布「图片 URL + 文字 + 元数据」的清单，使用者再用工具（如 img2dataset）自己去按 URL 下载图片。这么做一半是为了存储和带宽，一半是为了**绕开直接再分发他人图片的版权问题**——图片仍存在原网站，LAION 只提供「索引」。这个设计本身就暴露了网络数据在法律上的尴尬。

需要明确：LAION 把它定位为**面向研究的数据集**，附了内容警告，并不主张可以拿来无脑训练商用产品。这条「研究用途」的边界，后面会成为很多争议的焦点。

## 为什么经典

第一，它**打破了网络规模图文数据的垄断**。在它之前，这种数据是大公司的私有资产；LAION-5B 第一次把数十亿级、可复现的图文数据公开，直接让开源社区能复现 CLIP（OpenCLIP）、能训练文生图模型。**Stable Diffusion 就是在 LAION 的子集上训练出来的**——可以说没有 LAION，就没有那一波开源文生图的爆发。它把多模态大模型的「数据门槛」从少数玩家手里释放了出来。

第二，它**把「用模型过滤数据」固化成一套可复用的配方**。CLIP filtering 这种「拿现成模型当质量筛子、从脏网络数据里捞干净样本」的范式，被后续大量数据工程沿用和改进。它示范了在标注不可行的规模下，怎么用自动化手段构造训练集。

第三，也是对产品经理最重要的一点：它**把数据治理变成了一个公开的、必须正视的议题**。当你把整个开放网络当训练集，网络里所有的问题——社会偏见、版权纠纷、NSFW、甚至非法内容——都会被一并继承进数据、再进入模型行为。LAION-5B 后来围绕这些问题引发的连锁争议（详见下文），成了整个行业关于「训练数据从哪来、合不合规、出了问题谁负责」讨论的标志性案例。

划清边界：LAION-5B 的贡献是**开放的数据集和数据构造管线**，不是模型方法。CLIP 是别人的工作（它只是借用 CLIP 来过滤）；Stable Diffusion 的生成能力也不是 LAION 的贡献，LAION 提供的是「燃料」而非「引擎」。

## 产品经理启发

1. **对基础模型而言，数据是真正的产品输入，也是真正的护城河。** LAION-5B 的故事最直白地说明：方法和算力之外，能不能拿到足够规模、足够质量的数据，直接决定你能不能造出有竞争力的模型。PM 在规划任何依赖大模型能力的产品时，要把「数据从哪来、规模多大、质量如何、是否可持续」当作和模型选型同等重要的问题，而不是默认数据现成。

2. **「用模型清洗数据来训练下一个模型」会传递并放大偏见。** CLIP 过滤很高效，但它筛选的标准就是 CLIP 自己的判断，CLIP 学到的偏见会被带进 LAION，再被下一代模型继承——相当于偏见被「洗白」了一道、变得更隐蔽。PM 要警惕这种「模型清洗数据」的链条：自动化数据管线不是中立的，它的过滤器有自己的价值观和盲区，会一路传导到最终产品的行为里。

3. **拿开放网络当数据源，等于把网络的全部风险打包继承。** 偏见、版权、NSFW、违法内容——这些不是「小概率边角」，而是开放网络的固有成分，会变成下游产品的法律、品牌和安全风险。PM 在评估一个数据来源时，要问的不只是「质量够不够、规模够不够」，还有「它的法律出身和内容风险是什么、谁来兜底」。数据的合规性是产品风险的一部分，不能等上线后再救火。

4. **「数据可获得」不等于「可以拿来做产品」。** LAION 明确标注是研究用途，但很多人忽略这条边界。开源、能下载、免费，都不自动等于「商用安全、版权干净、合规可用」。PM 必须分清「研究数据集」和「可商用数据集」，把数据的使用条款、版权状态、内容合规作为上线前的尽调项，而不是看到「开源」二字就当作绿灯。

5. **规模和治理是一对此消彼长的成本。** 把整个网络一股脑捞进来，采集成本极低、规模极大，但代价是把巨大的治理负担推到下游（筛查、合规、风险处置）。更精细的人工策划数据干净，但贵、慢、难规模化。PM 要意识到这是一个权衡：省在前面的数据采集成本，往往会在后面以合规、安全、声誉风险的形式加倍偿还。便宜的规模不是免费的。

## 局限与争议

第一，**它继承了开放网络最严重的内容风险，并引发了真实的法律和安全事件。** 由于数据来自未经严格策划的网络抓取，LAION-5B 中混入了大量问题内容。最严重的是：2023 年底斯坦福的研究者在其中发现了儿童性虐待材料（CSAM），导致 LAION 一度将数据集下架，后来发布了经过清洗的版本（Re-LAION）。这是关于「web-scale 数据治理失控」最沉重的一课。

第二，**版权争议直接波及下游产品。** 数据集里包含大量受版权保护的图片（包括艺术家未经同意被抓取的作品），这成为针对在 LAION 上训练的文生图模型的多起诉讼的核心争点。「只发 URL 不发图片」的设计能减轻再分发的责任，但回避不了「拿这些图训练模型是否侵权」这个仍在争论中的根本问题。

第三，**CLIP 过滤是个粗糙且有偏的筛子。** 用相似度阈值卡「图文是否匹配」，既会漏掉好样本，也会放过对不上的样本；更关键的是它把 CLIP 的偏见带进了数据。alt 文本本身也是噪声很大的「弱监督」——很多描述笼统、含 SEO 关键词、或与图片只是松散相关。

第四，**只发 URL 带来「链接腐烂」（link rot）和不可复现。** 随着时间推移，越来越多原始图片 URL 失效，不同时间下载会得到不同的、缩水的数据集，损害可复现性，也让不同团队基于「同一个 LAION」得到的其实不完全一样。

第五，**质量在语言和文化上不均衡。** 英文部分相对最完善，其他语言和长尾文化的数据质量、覆盖度更弱，过滤阈值也以英文为主调，容易把非英语世界的语义对齐做得更差。

## 今天怎么看

今天看 LAION-5B，它有两副面孔：一面是开源多模态浪潮的奠基性燃料，另一面是数据治理的标志性警示案例。两面都重要，不能只记一面。

仍然重要的部分：

- **开放、可复现的网络规模数据集**这个理念，依然是开源社区能跟上闭源大厂的关键前提；
- **用模型过滤数据（CLIP filtering）** 作为大规模数据构造的基本范式，被持续沿用和改进；
- **「把开放网络当训练集 = 继承它的全部问题」** 这个治理认知，已经成为整个行业的共识起点；
- **数据的法律出身、内容合规、使用条款** 作为产品风险的一部分，越来越被当作上线前的硬约束。

已经被反思或推进的部分：

- 出于安全和合规，原始 LAION-5B 经历下架与清洗，社区转向更注重内容审查的版本（Re-LAION）；
- 业界逐渐认识到「相似度过滤」不等于「质量」，转向更精细的策划、去重，以及用模型**重写图片描述（recaptioning，如 DALL·E 3 的做法）** 来提升图文对齐质量，而不是只靠抓来的 alt 文本；
- 版权、同意机制、数据来源透明度成为持续的法律与监管议题，「能抓到就能用」的默认假设正在被挑战。

对 AI 产品经理来说，LAION-5B 最该带走的判断是：**训练数据既是能力的来源，也是风险的来源，而且这两者往往是同一批数据的一体两面。** 越是靠「把整个网络捞进来」获得规模和能力，就越要为偏见、版权、违法内容和合规埋单。在选数据、选模型、上产品时，把「这批数据的出身和风险」当作一等问题来尽调，是这篇论文留给产品人最实用、也最沉重的一课。

- 外部即便懂方法、有算力，也因为「拿不到同等规模的数据」而复现不出来，能力被数据的不可得卡住。
- LAION-5B 把网络规模、可复现的图文数据开放出来，解决的是「数据可得性」瓶颈，而不是模型方法。

2. 用自己的话解释 CLIP 过滤（CLIP filtering）是怎么工作的。它高效，但埋了什么隐患？

<details>
<summary>参考要点（先自己答，再展开）</summary>

- 用现成 CLIP 模型把图和文字各编码成向量，计算相似度，只保留高于阈值的「图文匹配」对，扔掉对不上的噪声。
- 思路是「用已有模型当质量筛子，给训练下一代模型的数据做清洗」，可规模化、不需人工。
