# RefinedWeb：The RefinedWeb Dataset for Falcon LLM: Outperforming Curated Corpora with Web Data, and Web Data Only

> 分类：数据集与数据治理  
> 年份：2023  
> 论文：https://arxiv.org/abs/2306.01116  
> 状态：reviewed

## 一句话

RefinedWeb 推翻了当时一个流行假设——「训大模型必须掺入维基百科、书籍、论文这类人工精选语料，光靠网页数据太脏不行」；它证明只要**过滤够狠、去重够彻底**，单纯的网页数据（而且只用网页数据）也能训出不输甚至超过精选语料的模型（论文用 1.3B/7.5B 的纯网页模型验证了这点；产品级的 Falcon 则以 RefinedWeb 为主、再叠加少量精选语料）；它把大模型数据的胜负手，从「去哪儿找好语料」重新定义成「有没有一条够强的清洗与去重管线」。

## 背景问题

大模型要吃海量 token。按 scaling law / Chinchilla 的结论，模型越大越要配更多训练数据，动辄上万亿 token。这就带来一个现实矛盾。

当时主流的「高质量数据」配方，是以人工精选语料为骨架：维基百科、出版书籍、arXiv 论文、新闻、代码仓库等，再混一些网页。代表是 The Pile 这类数据集。背后的信念是：**网页数据（Common Crawl 抓来的那种）又脏又杂、充满垃圾和重复，不能当主食，只能当配菜；真正撑质量的得靠人工策划的干净来源。**

但这条路有个天花板：**精选语料是有限的**。全世界的优质书籍、百科、论文加起来就那么多 token，喂不饱越来越大的模型。而**网页数据几乎是唯一能规模化到数万亿 token 的来源**——可它又被认为质量太差。

于是行业卡在一个两难里：能规模化的（网页）被认为不够好，够好的（精选）又不够多。RefinedWeb 的问题意识非常直接：**网页数据真的天生不行吗？还是只是因为我们没把它处理干净？如果把过滤和去重做到极致，光靠网页能不能顶起整个训练？**

## 核心方法

RefinedWeb 的答案是：问题不在原料，而在加工。它构建了一条叫 **MacroData Refinement（MDR）** 的数据处理管线，从 Common Crawl 这堆原始网页里，提炼出大规模高质量文本（论文产出约 5 万亿 token，并公开放出其中约 6000 亿 token 的子集）。它的功夫全在「怎么把脏网页洗干净」，重点是两件事：**狠过滤**和**狠去重**。

### 1. 更好地把正文从网页里抽出来

很多网页数据集直接用 Common Crawl 预处理好的纯文本（WET 文件），但那东西质量一般，混着大量导航栏、广告、页脚之类的样板文字（boilerplate）。RefinedWeb 选择从更原始的网页存档（WARC）出发，用更好的正文提取工具（trafilatura），尽量只留下网页真正的主体内容。**输入质量从源头就抓起。**

### 2. 狠过滤：从 URL 到文档到行，层层筛

- **URL 层过滤**：用黑名单挡掉成人、垃圾、诈骗等明显有害或低质的站点。
- **语言识别**：用 fastText 判定语言，聚焦目标语言（主要是英文），扔掉识别不清的。
- **文档级质量启发式**：借鉴 Gopher 等工作的规则，按文本长度、重复程度、符号/标点比例、单词特征等，把明显是垃圾、乱码、机器生成的低质文档刷掉。
- **行级过滤**：在文档内部再清理，去掉重复出现的样板行、导航文字等噪声。

这些规则不花哨，但叠起来能把网页里绝大部分垃圾过滤掉——最终能通过的内容只是原始网页的一小部分。

### 3. 狠去重：这是质量的真正大杀器

RefinedWeb 把**去重（deduplication）当成头等大事**，做得比当时多数数据集都激进，既做精确去重，也做模糊去重（用 MinHash 找近似重复、用后缀数组找长串重复），在超大规模上把重复内容大量删掉。

为什么去重这么关键？网络上同一段内容被无数站点转载、镜像、模板化重复。不去重的话：

- **浪费算力**：模型反复在同样的内容上训练，token 花了、收益低；
- **导致记忆与「背诵」**：高频重复内容容易被模型逐字背下来，推理时原样吐出，带来隐私泄露和版权复述风险；
- **拉低质量**：重复让数据的有效多样性下降，相当于「看起来很多，其实在反复看同一批东西」。

RefinedWeb 的核心论点之一就是：**充分去重 + 充分过滤，是把网页数据从「不能用」变成「能当主食」的关键。**

### 结论：网页，而且只要网页

论文用纯 RefinedWeb 训练的 1.3B、7.5B 模型，在当时与依赖精选语料的同规模模型相比有竞争力甚至更好——这是「web-only 够用」的直接证据。（后来公开的 Falcon-7B/40B 受 RefinedWeb 启发、以它为主，但实际叠加了部分 curated 语料，并非纯网页。）这就支撑了那个反直觉的标题——**Outperforming Curated Corpora with Web Data, and Web Data Only**：处理得当的网页数据，单独就够了。

划清边界：RefinedWeb 的贡献是**一条数据过滤/去重管线和由此得到的开放数据集**，以及「网页数据经充分处理可媲美精选语料」这个论断。它不是模型方法，Falcon 的模型架构是另一回事；它也不是说「精选数据毫无用处」，而是说「在当时的对比下，光靠处理好的网页就能打平甚至超过」。

## 为什么经典

第一，它**改写了大模型数据的核心假设**。在它之前，主流相信质量来自「来源」（要掺精选语料）；RefinedWeb 论证质量更多来自「处理」（过滤 + 去重）。同样一堆原始网页，处理得好不好，结果天差地别。这把数据工作的重心，从「四处搜罗稀有优质语料」转向「把唾手可得的网页认真清洗」。

第二，它**为「数据规模」松了绑**。精选语料有上限，而网页能规模化到万亿 token 级。一旦证明网页经处理就够好，等于打通了「按 scaling law 不断加数据」所需要的、近乎无限的干净 token 来源。这对继续扩大模型规模是关键前提。

第三，它**把去重确立为一等的数据质量杠杆**。在 RefinedWeb 之后，激进去重成了严肃数据管线的标配，去重的价值（省算力、抑制记忆/背诵、提升多样性）被广泛接受。

第四，它**推动了开源数据生态**。RefinedWeb 公开了大规模子集，加上同期/后续的 RedPajama、Dolma，以及它精神上的继承者 **FineWeb / FineWeb-Edu**（由同一核心作者主导，把「狠过滤狠去重的开放网页数据」做得更系统），让开源社区有了能与闭源大厂掰手腕的训练语料。

## 产品经理启发

1. **数据的胜负手常在「加工」而非「来源」。** 同样是网页这堆原料，过滤和去重做得好不好，决定它是垃圾还是主食。这对 PM 排数据投入优先级很有指导意义：与其花大力气去搜罗、采购稀有的「优质数据源」，不如先把已经能拿到的数据的清洗、去重、质量管线做扎实——后者的边际回报往往更高、更可控。

2. **去重不只是省成本，更是合规和风险的杠杆。** 重复内容会让模型逐字背诵、推理时原样吐出，直接关联隐私泄露和版权复述风险。把去重当成数据管线的头等公民，既省算力、又提质量、还降低「模型背出训练数据」的法律和品牌风险。PM 在评估数据治理时，应把去重力度当作一个明确的质量与合规指标，而不是工程细节。

3. **「干净的规模」才是真正能喂大模型的资源。** 精选语料有天花板，网页才能撑起万亿 token。若产品路线依赖持续扩大的训练/微调数据，PM 要意识到：可持续的规模来自「能把大体量脏数据清洗干净的能力」，而不是寄望于有限的精品语料。数据管线本身就是一种可复利的核心资产。

4. **质量是被「过滤器」定义出来的，过滤器带着价值判断。** RefinedWeb 最终只留下原始网页的一小部分，「留谁、删谁」由一套规则决定，而这套规则隐含了「什么算高质量」的判断。这意味着过滤会系统性地塑造（也可能偏置）数据——比如过度的质量/毒性过滤可能误删某些方言、少数群体或非主流表达。PM 要明白：数据清洗不是中立操作，过滤策略会一路影响模型的能力边界和公平性，需要被审视而非默认正确。

5. **「精炼已有的」常常胜过「再去搞更多的」。** RefinedWeb 的内核是 refine（精炼）而非 collect（搜集）。这是一个可迁移的产品判断：很多时候，把手头数据/资产的质量做上去，ROI 高于不断扩张获取新来源。在数据预算有限时，先问「现有数据还能再榨出多少质量」，往往比「再买/再爬一批」更划算。

## 局限与争议

第一，**「质量」是用启发式规则和基准分数定义的，带主观与偏置。** 什么算高质量，由一套人工规则和下游 benchmark 表现来判定。这些过滤器可能误删合理内容，也可能把某种「主流书面英语」当成质量标准，从而系统性地削弱方言、少数群体、非英语和非主流表达的覆盖。过滤越狠，这种隐性偏置的风险越大。

第二，**「网页就够了」是有时代与任务边界的结论。** 它成立于当时与精选语料基线（如 The Pile 时代）的对比，且主要针对通用语言建模能力。对代码、数学、复杂推理等特定能力，后续实践发现掺入高质量代码、数学和**精选/合成数据**仍然有明显帮助。所以「web only」不应被外推成「精选数据永远没用」——今天的前沿训练恰恰大量混用精选、代码与合成数据。

第三，**公开的只是子集，完整数据未全部释放。** 论文产出约 5 万亿 token，但公开的是约 6000 亿 token 的提取版，完整规模和最优配方并未全部开放，可复现性有限。

第四，**狠过滤意味着丢掉绝大部分网页。** 能通过管线的只是原始网页的一小部分，这在带来质量的同时，也意味着大量信息被舍弃，且「舍弃标准」本身就是一组需要被审视的选择。

第五，**激进去重和高质量正文提取计算开销不小。** 在万亿 token 规模做模糊+精确去重、做更精细的正文抽取，本身是重工程，门槛不低，并非任何团队都能轻易复刻。

## 今天怎么看

今天看 RefinedWeb，它最持久的贡献不是某个具体数据集，而是一个已被行业广泛接受的判断：**大模型数据的质量主要由处理（过滤 + 去重）决定，而不是由是否掺入稀有精选语料决定；处理得当的网页，足以成为训练的主食。**

仍然重要的部分：

- **「处理 > 来源」** 这个数据工作的重心转移，已成为共识；
- **狠去重** 作为质量、算力效率和记忆/版权风险的核心杠杆，是严肃数据管线的标配；
- **可规模化的干净网页数据** 是支撑模型继续按 scaling 扩张的关键资源；
- 它推动的**开放数据生态**（直到 FineWeb / FineWeb-Edu 等继承者）仍在让开源社区保持竞争力。

已经被推进或修正的部分：

- 「web only」在前沿实践中被「网页为主 + 精选 + 代码 + 数学 + **合成数据**」的混合配方取代，特定能力仍要靠精选/合成数据补强；
- 过滤标准带来的偏置、对少数表达的削弱，得到更多反思，数据治理从「越干净越好」转向「干净但要警惕过滤偏见」；
- 数据质量的衡量从粗糙启发式，发展出更精细的质量分类器、教育性打分（如 FineWeb-Edu）等手段。

对 AI 产品经理来说，RefinedWeb 给的最实用一课是：**别迷信「神秘优质数据源」，先把数据处理（过滤、去重、质量管线）当成核心能力来投入；同时清醒地知道，你的过滤器不是中立的，它在定义什么算「好」，也在悄悄塑造模型的能力和偏见。** 数据工程不是脏活累活的附属，它本身就是产品质量、成本和合规的主战场。
