# Tülu 3：Tülu 3: Pushing Frontiers in Open Language Model Post-Training

> 分类：后训练与对齐  
> 年份：2024  
> 论文：https://arxiv.org/abs/2411.15124  
> 状态：draft

## 一句话

Tülu 3 是 Allen Institute（AI2）在 2024 年放出的一套**完全开放的后训练配方**——它不只发布模型权重，还把「怎么把一个开源基座模型调成好用助手」的全套数据、代码、评测和决策过程都公开了，用「监督微调 SFT → 直接偏好优化 DPO → 基于可验证奖励的强化学习 RLVR」三段式，把开放后训练的效果推到接近当时闭源前沿，让后训练这件长期被各大厂当商业机密的事，第一次有了一份可复现、可审计、可在上面继续改的公共参考。

## 背景问题

到 2024 年，一个尴尬的现实是：**预训练越来越开放，后训练却越来越黑箱**。

很多团队会开源基座模型的权重（甚至预训练数据），但真正决定「这个模型用起来好不好、听不听话、会不会做数学和指令」的那一段——后训练——却几乎总是闭源的。前沿实验室把后训练的数据配比、偏好数据来源、强化学习的具体做法当成核心竞争力，对外只给一个「我们做了 RLHF」的笼统说法。

这造成了几个问题：

- **复现难**。研究者拿到一个开源基座，想复刻它变成好用助手的那一步，往往只能靠猜，缺数据、缺配方、缺评测标准。
- **进步不透明**。后训练的每一个改进（换了什么数据、用了什么算法）到底贡献多少，外部无从验证，容易被营销话术掩盖。
- **评测被污染**。很多「刷榜」其实是测试集泄漏（数据污染）或针对榜单过拟合，缺少干净、可信、可复现的评测协议。

同时，后训练本身也在快速演进：从 InstructGPT 的 SFT + 奖励模型 + PPO，到更轻量的 DPO（直接用偏好数据优化、跳过显式奖励模型和 PPO），再到针对数学/代码等可验证任务的新思路。社区需要的不是又一个「黑箱很强」的模型，而是一份**把这些新方法整合起来、并且每一步都摊开给你看**的开放配方。

Tülu 3 的问题意识正是：**能不能把一套达到接近前沿水平的后训练流程，连同数据、代码、评测一起完全开放，让任何人都能复现、审计、并在上面继续往前推？**

> 注意时效：Tülu 3 是 2024 年底的成果，处在后训练方法高速迭代的阶段。它的具体数字和「接近前沿」的定位是那个时间点的快照；它真正持久的价值在于**开放的配方和方法论**，而不是某个会很快被刷新的榜单名次。

## 核心方法

Tülu 3 的贡献与其说是某个全新算法，不如说是一套**被完整公开、且认真做了消融和评测的后训练流水线**。核心是三段式。

### 1. SFT：先用高质量、多样化的数据打底

第一阶段仍是监督微调，但重点在数据工程。Tülu 3 强调**数据的多样性和质量管理**：覆盖通用对话、数学、代码、精确指令遵循、安全等多种能力的 prompt-完成对，并做严格的去重、清洗，以及关键的——对评测集做**去污染**（decontamination），保证训练数据里没有偷偷混进测试题。这一步决定了模型的基本盘和能力覆盖。

### 2. DPO：用偏好数据直接对齐，跳过 PPO 的复杂

第二阶段做偏好对齐，但用的是 **DPO（Direct Preference Optimization）** 而不是 InstructGPT 式的「奖励模型 + PPO」。

DPO 的核心思路：既然我们有「同一个 prompt 下，人类/模型更偏好 A 还是 B」的成对数据，那其实可以**直接**用一个简洁的损失函数，让模型提高被偏好回答的概率、压低被拒绝回答的概率——不需要先单独训练一个奖励模型，也不需要跑不稳定、难调参的 PPO 强化学习。它把 RLHF 里那一大段流程，压缩成了一个更像普通监督训练的步骤，工程上简单得多、也更稳定。Tülu 3 在这一步同样大量投入在**偏好数据的构造和配比**上。

### 3. RLVR：在「能验证对错」的任务上做强化学习

第三阶段是 Tülu 3 最有时代特征的一招：**RLVR（Reinforcement Learning with Verifiable Rewards，基于可验证奖励的强化学习）**。

回想 InstructGPT 的痛点：奖励来自一个**学出来的**奖励模型，它是人类偏好的近似，会被钻空子（reward hacking），也分不清「听起来对」和「真的对」。RLVR 换了个思路：在那些**答案对错可以被程序自动验证**的任务上——比如数学题（答案能算、能核对）、有明确格式约束的指令遵循（能用规则检查是否满足）——干脆**不用学习型奖励模型，直接用「验证器判对错」作为奖励信号**去做强化学习。答对给正奖励，答错不给。

这么做的好处很直接：奖励是**客观、可验证、不可钻空子**的，模型没法靠「显得自信」骗到分，只能真的把题做对。代价是它只适用于「对错可判定」的领域，对开放式写作、主观偏好这类无法自动验证的任务不适用——所以 RLVR 是 DPO 的补充而非替代，两者各管一段。

### 4. 把整套东西连同评测一起开放

除了三段式配方，Tülu 3 还公开了**训练数据、训练代码、以及一套标准化的评测框架**（带去污染、带一组覆盖多能力的评测集）。这套评测框架本身是贡献的一部分——它让「我的后训练改进到底有没有用」变得可测量、可比较、可复现，而不是各说各话地刷榜。

### 归因红线

- Tülu 3 的定位是**开放配方 / 开放数据 / 开放评测**，不是「发明了 DPO 或 RL」。DPO 是更早的工作，RL 用于对齐也不是它首创——它的贡献在于**把这些方法整合成一套达到接近前沿、且完全可复现的开放流程，并把 RLVR 系统化地放进开放后训练里**。
- 它是某个**时间点（2024）的开放后训练 state-of-the-art**，不是一个永恒结论。把它的具体榜单数字当成长期事实是错的；它会被自己的后续版本和别人的工作刷新。

## 为什么经典

第一，它把后训练从黑箱拉到了阳光下。在「大家都开源权重、却没人开源配方」的局面里，Tülu 3 提供了第一份认真、完整、可复现的公共后训练参考，相当于给整个开放社区发了一本「怎么把基座调成助手」的公开教科书。

第二，它示范了一套**与时俱进的后训练组合**：SFT 打底、DPO 做偏好对齐、RLVR 在可验证任务上拔高。这条「SFT + 偏好优化 + 可验证强化」的路线，正好踩在 2024 年后训练演进的方向上。

第三，它把**评测的严谨性**当成一等公民。去污染、标准化评测框架、公开的消融，这些「不性感但要命」的工程，让开放社区第一次能在同一把尺子上比较后训练的改进。

第四，RLVR 这条线把后训练和「可验证奖励驱动的推理能力」连了起来——这正是同期 o1 一代推理模型崛起背后的共同主题之一。Tülu 3 是这个主题在**开放、可复现**这一侧的重要代表。

## 产品经理启发

1. **「拿到一个开源基座」离「拿到一个好用助手」还差一整段后训练。** 很多团队以为下载了开源权重就万事大吉，其实模型好不好用，关键在后训练这一段。Tülu 3 把这段的工作量和决策点摊开给你看——评估自研可行性时，要把后训练的数据、算力、评测投入单独算一笔账。

2. **后训练的胜负手，很大程度在数据工程而非算法新奇度。** Tülu 3 大量篇幅花在数据多样性、配比、清洗、去污染上。对 PM 的启示是：与其追最新的训练算法，不如先把「用什么数据、怎么配比、怎么保证没泄漏」这件最朴素的事做扎实。

3. **「能不能自动验证对错」决定了你能用哪种对齐手段。** RLVR 的适用边界很清楚：可验证任务（数学、有格式约束的指令）能用客观奖励，开放式任务只能靠偏好。做产品时，先判断你的任务属于哪一类——可验证的部分，可以追求「真的做对」；不可验证的部分，只能优化「人更偏好」。这直接影响你的数据和评测策略。

4. **可验证奖励能挡住「听起来对」的陷阱。** 学习型奖励模型容易被自信的废话骗分，而验证器只认对错。如果你的场景里正确性可以被程序检查（代码能跑、数值能核、约束能验），优先把这部分变成可验证奖励/可验证评测，比单纯靠人评或模型评更可靠。

5. **开放配方降低了「站在巨人肩上」的门槛。** Tülu 3 这类完全开放的配方，意味着你不必从零摸索后训练，可以直接复用一份经过验证的流程作为起点，再针对自己的场景改。做技术选型时，「有没有可复现的开放参考」本身就是一个该被纳入考量的因素。

6. **评测协议和数据去污染，是产品可信度的底座。** Tülu 3 把去污染和标准化评测当核心贡献——因为没有干净评测，所有「提升」都可能是幻觉。做 AI 产品时，建一套不被训练数据污染、能稳定复现的内部评测，比多刷几个点的榜单分数重要得多。

## 局限与争议

第一，它是高速领域里的一个时间快照。2024 年的「接近前沿」会被很快刷新，具体数字、具体配比都有时效。把 Tülu 3 当成「后训练的最终答案」是错的——它的价值在方法论和开放性，不在某一版的名次。

第二，「开放」不等于「最强」。完全开放的配方在透明度上无可替代，但在绝对效果上，未必超过那些用海量私有数据和算力堆出来的闭源前沿模型。开放和领先之间通常还有差距。

第三，RLVR 的适用范围有限。它只在「对错可自动判定」的领域有效；对开放式写作、创意、主观偏好、复杂多轮对话这些无法自动验证的任务，仍要回到偏好数据，无法享受「客观奖励」的好处。

第四，它高度依赖基座模型的质量。后训练能把基座的能力对齐、激发出来，但补不上基座本身缺失的能力。同一套 Tülu 3 配方，套在弱基座上和强基座上，天花板完全不同——这条边界和 InstructGPT「对齐 ≠ 能力」是一脉相承的。

第五，复现成本仍然不低。「开放」让复现成为可能，但跑通完整三段式后训练、加上数据构造和评测，仍需要可观的算力和工程能力，对很多小团队依然是门槛。

第六，数据与评测的覆盖偏向。其数据和评测仍以英语、特定任务类型为主，对多语言、特定垂直行业、特定文化语境的覆盖有限——直接搬用未必适配你的具体场景。

## 今天怎么看

把 Tülu 3 放进当前生态，它的意义不在「又一个开源模型」，而在它定义并公开了一套**可复现的现代后训练方法论**：SFT 打底、DPO 对齐、RLVR 在可验证任务上拔高，再配一套严谨评测。

仍然重要的部分：

- 「开放配方 + 开放数据 + 开放评测」作为对抗后训练黑箱化的范式；
- 「可验证奖励」这一思路——它和同期推理模型（用 RL + 可验证奖励训练长链推理）的兴起同源，是理解 2024–2025 推理浪潮的一把钥匙；
- 「后训练胜负手在数据工程和评测严谨性」这一务实判断；
- 「对齐受限于基座能力」这条和 InstructGPT 共通的边界。

需要动态看待的部分：

- 具体的模型版本、数据配比、榜单数字会被后续版本和新工作持续刷新；
- DPO、RLVR 等只是当前阶段的主流选择，后训练算法仍在快速演进；
- 「开放最强」与「闭源前沿」之间的差距会随时间变化，需结合最新进展判断。

对 AI 产品经理来说，Tülu 3 是一面镜子：它照出「把基座变成好用助手」这一步到底包含哪些真实工作——数据、偏好、可验证奖励、去污染评测，每一项都不性感却都要命。它也提醒我们，在一个充满营销话术的领域，**可复现、可审计的开放配方**本身就是一种稀缺价值。

3. 什么是 RLVR？相比学习型奖励模型，「可验证奖励」的优势和适用边界分别是什么？

<details>
<summary>参考要点（先自己答，再展开）</summary>

- RLVR：在答案对错可被程序自动验证的任务上，直接用验证结果当奖励做强化学习，不用学习型奖励模型。
- 优势：奖励客观、可验证、不可钻空子，模型靠「显得自信」骗不到分，只能真做对。
- 边界：只适用于对错可判定的领域（数学、有格式约束的指令）；开放式/主观任务不适用，仍需偏好数据。
